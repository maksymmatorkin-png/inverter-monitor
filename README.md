# Мониторинг инвертора LuxPower → Telegram

Скрипт работает в GitHub Actions, каждые 2 минуты читает портал
[eu.luxpowertek.com](https://eu.luxpowertek.com) и пишет в Telegram-группу только то,
что важно знать жильцам:

| Событие | Когда приходит |
|---|---|
| 🌑 Свет пропал | напряжение сети упало ниже 170 V; сразу с прогнозом, на сколько хватит батареи |
| 💡 Свет появился | с длительностью отключения и тем, насколько села батарея |
| 🔋 Заряд 50 / 30 / 20 / 10 % | только во время отключения, с прогнозом времени работы |
| ⚠️ Большая нагрузка | больше 4500 W на резервном выходе при работе от батареи |
| 📡 Инвертор не на связи / снова на связи | данных нет дольше 20 минут |
| ❗ Ошибка инвертора | появился или сбросился код ошибки или предупреждения |
| 🥶 🔥 Температура батареи | ниже 5 °C или выше 45 °C |
| 📊 Итоги дня | в 21:00: отключения, минимум заряда, потребление |
| ⚠️ Портал недоступен | 3 неудачных запуска подряд |

Когда всё спокойно, бот молчит.

## Установка

### 1. Бот в Telegram

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, задайте имя и логин бота.
   В ответ придёт **токен** вида `1234567890:AA...` — это `TG_BOT_TOKEN`.
2. Добавьте бота в группу, куда должны приходить сообщения.
3. Напишите в группе любое сообщение с упоминанием бота, например `@ваш_бот привет`.
4. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   и найдите `"chat":{"id":-100...` — это `TG_CHAT_ID` (у групп он отрицательный, минус обязателен).
   Если ответ пустой (`"result":[]`), напишите в группу ещё раз и обновите страницу.

### 2. Репозиторий на GitHub

1. Создайте **публичный** репозиторий и загрузите в него файлы этой папки.
   У публичных репозиториев минуты Actions бесплатны и не ограничены; у приватного
   2000 бесплатных минут в месяц закончатся примерно за неделю.
2. Логин, пароль, серийный номер и токен в файлы **не записывайте** — только в секреты.

### 3. Секреты

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.

| Секрет | Значение |
|---|---|
| `LUX_ACCOUNT` | логин портала LuxPower |
| `LUX_PASSWORD` | пароль портала |
| `LUX_SERIAL` | серийный номер инвертора (10 символов, виден в портале и на наклейке) |
| `TG_BOT_TOKEN` | токен от BotFather |
| `TG_CHAT_ID` | id группы |

Совет: заведите в портале отдельного пользователя только с правом просмотра
и используйте его логин, а не основную учётную запись.

Название в сообщениях («Квартира») меняется на вкладке **Variables**: переменная `SITE_NAME`.

### 4. Запуск

1. Вкладка **Actions** → если GitHub просит, нажмите *I understand my workflows, go ahead and enable them*.
2. Выберите **Мониторинг инвертора → Run workflow** (галочка «Прислать текущий статус» включена).
3. Через минуту в группу придёт «🤖 Мониторинг инвертора запущен» с текущим статусом.

Дальше всё работает само. Тот же **Run workflow** в любой момент присылает текущий статус.

## Что стоит знать

- **Непрерывный режим.** Запуск «Мониторинг инвертора» работает около 25 минут, проверяет
  инвертор каждые 2 минуты и в конце сам запускает следующий. Сообщение приходит через 2–3 минуты
  после события. На расписание GitHub полагаться нельзя: оно опаздывает на десятки минут.
- **Сторож.** Workflow «Сторож мониторинга» дважды в час проверяет, что цепочка жива,
  и перезапускает её, если она оборвалась. Вручную цепочку запускает **Run workflow**.
- **Остановить мониторинг:** Actions → «Мониторинг инвертора» → **⋯ → Disable workflow**,
  то же для «Сторож мониторинга», затем отменить текущий запуск.
- **Интернет.** Если роутер не запитан от инвертора, при отключении света придёт
  «Инвертор не на связи», а не «Свет пропал».
- **Журналы публичны**, поэтому показаний инвертора в них нет: только строки
  `OK: проверка выполнена, сообщений: 0`. Логина, пароля, токена и серийного номера там тоже нет.
- **Состояние** между запусками (`state.json`) хранится в кэше Actions, в репозиторий не попадает.
- **Keepalive.** GitHub отключает расписание в репозиториях без активности 60 дней,
  поэтому раз в 45 дней workflow сам делает пустой коммит.
- **Порог определения отключения** (сеть ниже 170 V или 45 Hz) проверен на реальном отключении:
  без света инвертор показывает 0 V, со светом около 235 V.

## Настройки

Необязательные переменные (**Settings → Secrets and variables → Actions → Variables**;
чтобы они дошли до скрипта, добавьте их в блок `env` шага «Проверить инвертор» в
`.github/workflows/monitor.yml` по образцу `SITE_NAME`):

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `SITE_NAME` | `Квартира` | название в сообщениях |
| `SOC_ALERTS` | `50,30,20,10` | пороги заряда, % |
| `CUTOFF_SOC` | `10` | заряд, на котором инвертор прекращает разряд |
| `OVERLOAD_W` | `4500` | порог предупреждения о нагрузке, W |
| `OFFLINE_MIN` | `20` | через сколько минут без данных считать, что связи нет |
| `SUMMARY_HOUR` | `21` | час вечерней сводки, `-1` — выключить |
| `BAT_TEMP_LOW` / `BAT_TEMP_HIGH` | `5` / `45` | границы температуры батареи, °C |
| `TIMEZONE` | `Europe/Kyiv` | часовой пояс |

## Проверка на своём компьютере

Нужен Python 3.9 или новее.

```bash
pip install -r requirements.txt
```

Сценарные тесты (сеть и секреты не нужны):

```bash
python tests/test_scenarios.py
```

Пробный запуск с реальным порталом без отправки в Telegram (переменные `LUX_ACCOUNT`,
`LUX_PASSWORD`, `LUX_SERIAL` должны быть заданы в окружении):

```bash
python monitor.py --dry-run --status
```

Флаги: `--dry-run` — печатать сообщения вместо отправки; `--status` — добавить текущий статус;
`--fixture файл.json` — взять ответы портала из файла; `--now 2026-01-15T10:00:00+02:00` — подменить время.
